# Explicit third-party package list -- deliberately NOT `-e ..` (an earlier
# version of this file used that, reasoning that pip resolves a requirements
# file's local editable-install paths relative to the FILE's own location,
# not the invocation directory; verified locally, but that local test ran
# with cwd already inside demo_app/, which couldn't actually distinguish
# "relative to the file" from "relative to cwd" since they were the same
# directory -- a real gap in that verification. If Streamlit Community
# Cloud's installer invokes pip from the repo root instead, `-e ..` resolves
# to one level ABOVE the repo, finds no pyproject.toml there, and installs
# nothing -- which is exactly the failure this file is now written to avoid
# depending on either way.
#
# This list mirrors pyproject.toml's own `dependencies` exactly (keep them
# in sync by hand -- small, stable list, not worth a generation step). The
# first-party `sonic_explorer` package itself is NOT pip-installed by this
# file at all -- Demo.py inserts the repo root onto sys.path directly (see
# its own comment), so `import sonic_explorer` resolves as a plain
# source-tree import, independent of whatever pip/cwd quirks Cloud's
# installer has. Two completely separate, independently-robust mechanisms
# for the two different things this app needs: real PyPI packages here,
# this repo's own package via sys.path.
